============================================================
PART 1 — ControllerEndpointBuilder
============================================================

Add a new production file, for example:

ClashX/General/Utils/ControllerEndpointBuilder.swift

The builder must construct safe controller HTTP and WebSocket URLs.

It must support:
- embedded controller base from ConfigManager.apiPort
- external controller base from ConfigManager.shared.overrideApiURL
- http -> ws conversion
- https -> wss conversion
- base URLs with or without trailing slash
- endpoint paths with or without leading slash
- query items
- URL-encoded path components where appropriate
- invalid base URL error reporting

Do not return strings if URL can be returned.
Prefer URL.

Proposed API shape:

enum ControllerEndpointError: LocalizedError {
    case coreStopped
    case invalidBaseURL(String)
    case invalidEndpoint(String)
}

enum ControllerEndpointBuilder {
    static func httpURL(path: String, queryItems: [URLQueryItem] = []) throws -> URL
    static func websocketURL(path: String, queryItems: [URLQueryItem] = []) throws -> URL
    static func baseHTTPURL() throws -> URL
    static func baseWebSocketURL() throws -> URL
}

Rules:
- "/configs" and "configs" must produce the same endpoint.
- "http://127.0.0.1:9090/" + "/configs" must produce "http://127.0.0.1:9090/configs", not "...//configs".
- "https://example.com:9090" websocket base should become "wss://example.com:9090".
- If external override URL has query or fragment, discard query/fragment for endpoint base.
- If external override URL includes userinfo, ignore userinfo for endpoint construction.
- Keep existing ConfigManager.apiUrl and ConfigManager.webSocketUrl for compatibility if needed, but new or touched code must not use raw string concatenation.

PART 5 — Add CoreCapabilityProbe
============================================================

CapabilityCache currently behaves as a passive dictionary. Add a minimal probe layer.

Add files such as:

ClashX/General/Managers/CoreCapabilityProbe.swift

Suggested types:

struct CoreCapabilitySnapshot {
    let controllerIdentity: String
    let mode: String
    let running: Bool
    let coreVersion: String?
    let statuses: [CoreCapability: CoreCapabilityStatus]
    let probedAt: Date
}

final class CoreCapabilityProbe {
    static let shared = CoreCapabilityProbe()
    func probeCurrentController(completion: @escaping (CoreCapabilitySnapshot) -> Void)
}

Rules:
- Do not store raw controller secrets in controllerIdentity.
- Use "secret-set" or a short non-reversible digest if secret presence must affect identity.
- Do not use mutating endpoints as probes.
- Do not call /cache/dns/flush as a probe.
- Do not call /restart as a probe.
- Do not call /upgrade/* as probes.
- Do not call /debug/gc as a probe.

Safe/minimal probe set:
- /version
- /configs
- /providers/proxies
- /providers/rules
- /memory
- /group/weights only if safe; otherwise mark smartWeights unknown until Smart Dashboard requests it
- /group if endpoint exists and is read-only

Optional:
- For dnsQuery, do not perform a real DNS query during automatic probing unless you choose a harmless local or invalid name and document why. It is acceptable to leave dnsQuery unknown until user action.

Capability semantics:
- Core stopped -> all controller-backed capabilities should become unavailable or unknown with "core stopped" message.
- 2xx -> available.
- 401/403 -> unauthorized.
- 404/405/501 or clearly unsupported -> unsupported.
- Network/decoding/other error -> degraded.
- Not probed -> unknown.

Update CapabilityCache:
- It may still store statuses.
- It should be able to accept a snapshot.
- It should be thread-safe enough for UI callbacks. Use a serial DispatchQueue or main-thread confinement with clear comments.
- Existing UI mark(...) calls may remain temporarily, but probe snapshot should be the baseline source of truth.

Integrate minimally:
- In AppDelegate after successful core start/reload, call CoreCapabilityProbe.shared.probeCurrentController.
- In CoreSettingViewController viewWillAppear or refreshAll, prefer snapshot/probe instead of relying only on unknown cache.
- In DiagnosticsDashboardViewController, avoid firing multiple endpoint requests when ConfigManager.shared.isRunning is false. Show stopped state first.
- In SmartDashboardViewController, use capability snapshot where available, but still allow manual refresh.

Do not over-engineer this into a full reactive system in this PR.
