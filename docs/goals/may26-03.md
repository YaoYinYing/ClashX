GOAL
============================================================

Create a new GitHub Actions workflow that runs after merge to smartx.

The workflow should:

1. Build the SmartX app on the modern lane.
2. Discover the built .app path robustly from xcodebuild build settings.
3. Package the app into a DMG.
4. The DMG should contain:
   - the built .app
   - an /Applications symlink
   - a background image that visually tells users to drag the app into Applications
5. Upload the DMG as a GitHub Actions artifact.
6. Use version naming:

v<SmartX-version>+<git-hash[:8]>

Example:

v1.2.3+abcdef12

If the app version is 1.2.3 and git hash is abcdef1234567890.

============================================================
VERSION NAMING
============================================================

The DMG version string must be:

v<SmartX-version>+<git-hash[:8]>

Define:

SHORT_SHA="${GITHUB_SHA::8}"

SmartX-version should come from the built app or build settings.

Preferred extraction order:

1. After build, inspect the built app Info.plist:
   CFBundleShortVersionString

2. If that fails, read MARKETING_VERSION from xcodebuild -showBuildSettings.

3. If that fails, use "0.0.0-unknown" and fail the workflow unless there is a strong reason not to.

Implementation suggestion:

APP_VERSION=$(/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" "$APP_PATH/Contents/Info.plist")

VERSION_TAG="v${APP_VERSION}+${SHORT_SHA}"

Use VERSION_TAG in artifact names and DMG file names.

Example output:

SmartX-v1.2.3+abcdef12.unsigned.dmg

Important:
Do not use git tag as the version source unless the app version is unavailable.
Do not include the full SHA in the user-facing version tag; use first 8 characters.

============================================================
APP PRODUCT DISCOVERY
============================================================

Do not hardcode SmartX.app.

The Xcode product may still be named SmartX.app or ClashX.app depending on PRODUCT_NAME/FULL_PRODUCT_NAME.

After build, discover the built app using xcodebuild build settings.

Required:

1. Run xcodebuild -showBuildSettings with the same workspace/scheme/configuration/derivedDataPath/deployment target parameters.

2. Extract:
   - BUILT_PRODUCTS_DIR
   - FULL_PRODUCT_NAME
   - WRAPPER_NAME
   - PRODUCT_NAME

3. Prefer:
   APP_PATH="${BUILT_PRODUCTS_DIR}/${FULL_PRODUCT_NAME}"

4. If FULL_PRODUCT_NAME is missing or APP_PATH does not exist:
   find "${DERIVED_DATA_PATH}/Build/Products/${BUILD_CONFIGURATION}" -maxdepth 1 -name "*.app" -type d

5. If exactly one .app is found, use it.

6. If zero or multiple .app candidates are found, fail with a clear message and upload logs.

Write discovery logs to:

.ci-logs/app-discovery.log

Create a DMG staging directory.

It must contain:

The mounted DMG should show a drag-to-Applications experience.

Use a background image.

Add a repo asset if one does not already exist, for example:

or

If generating a simple background programmatically is easier, create it in the workflow with Python or sips. But prefer committing a small static PNG if possible.

Background image requirements:

- Shows or implies app icon on the left and Applications folder on the right
- Include short text such as:
  "Drag SmartX to Applications"
- Keep it simple and clean
- No remote downloads
- No CDN assets

The DMG should visually support dragging the app to Applications using the symlink.

Implementation options:

Option A:

- app icon position
- Applications symlink position
- background image

Do not add heavyweight external dependencies unless already present.

Expected layout:

- Applications symlink at roughly x=440 y=180
- background image applied
- window size around 600x400 or 640x420

If Finder view scripting is unreliable on CI, still create a functional DMG with:

But attempt Finder layout first.

============================================================
DMG CREATION SCRIPT
============================================================

Prefer adding a reusable script:

scripts/create-dmg.sh

It should accept:

--app-path <path>
--version-tag <version>
--output-dir <dir>

or simple env vars:

APP_PATH
VERSION_TAG
OUTPUT_DIR

The script should:

1. Create a clean staging directory.
2. Copy the app bundle into staging.
3. Create Applications symlink.
4. Add .background/background.png or equivalent.
5. Optionally add README.txt.
6. Create a read-write temporary DMG.
7. Mount it.
8. Apply Finder view settings if possible.
9. Detach it.
10. Convert to compressed read-only UDZO DMG.
11. Compute SHA256 checksum.

Output:

.ci-dmg/SmartX-${VERSION_TAG}.unsigned.dmg
.ci-dmg/SmartX-${VERSION_TAG}.unsigned.dmg.sha256
.ci-dmg/README.txt

The README.txt should say:

"SmartX-vX.Y.Z+HASH.unsigned.dmg is an unsigned, non-notarized CI artifact. Drag SmartX.app to Applications for manual testing. Privileged helper behavior may not work in unsigned builds. This is not a release build."

Use set -euo pipefail.
Clean temporary mounts on failure.
