TASK 1: Remove hidden bootstrap side effects from Settings getters
============================================================

Problem:
Settings.effectiveSmartLightGBMModelUrl currently calls bootstrapSmartXManagedOverridesIfNeeded().
Settings.syncSmartLightGBMOptionsToCore() also calls bootstrapSmartXManagedOverridesIfNeeded().
LightGBMSettingsViewModel.currentState() also bootstraps.

This is dangerous because a getter can now trigger disk IO, migration, file creation, and UserDefaults mutation. It also risks call chains like:

Settings getter
→ bootstrap
→ captureFromSettings
→ Settings getter

Goal:
Override bootstrap must be explicit and idempotent, not hidden inside low-level Settings getters.

Required changes:

1. Keep SmartXManagedOverrideManager.bootstrapIfNeeded() idempotent.

2. Call bootstrap explicitly from app startup or feature-entry points.
   Existing AppDelegate.startProxy() already calls Settings.bootstrapSmartXManagedOverridesIfNeeded(); keep this path.

3. Remove bootstrap from Settings.effectiveSmartLightGBMModelUrl.

4. Remove bootstrap from Settings.syncSmartLightGBMOptionsToCore().
   This method should sync current effective values into the core.
   It should not migrate files.

5. If LightGBMSettingsViewModel.currentState() still calls bootstrap, document that this is a UI-entry migration point.
   It must not repeatedly write files after the first bootstrap.

6. Ensure SmartXManagedOverrideManager.captureFromSettings() reads raw Settings values, not Settings.effectiveSmartLightGBMModelUrl if that getter may bootstrap.

7. Add comments explaining:
   - override bootstrap is migration/setup
   - Settings getters must not write files
   - UserDefaults is now compatibility cache
   - the persisted SmartX override file is the first durable managed override source

Acceptance criteria:
- Reading Settings.effectiveSmartLightGBMModelUrl does not create or write files.
- syncSmartLightGBMOptionsToCore() does not perform migration.
- App startup and LightGBM UI still load migrated override values.
- The managed override smoke harness covers the no-hidden-write behavior if practical.
