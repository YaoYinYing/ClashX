BLOCKER 1: Future-schema override protection is incomplete
============================================================

Problem:
SmartXManagedOverrideManager protects future schema files only if they can still decode into SmartXManagedOverride.

Current behavior:
- load() calls decodedOverride().
- decodedOverride() returns nil if JSON cannot decode into the current model.
- bootstrapIfNeeded() treats nil as "no override file".
- If legacy UserDefaults exist, bootstrapIfNeeded() captures settings and save() writes a current-schema override file.

This means an incompatible future-schema file or structurally changed override file can be overwritten during bootstrap if legacy settings exist.

This violates the intended future-schema preservation behavior.

Required fix:

1. Add a raw-file existence and schema probing path.

Suggested design:

enum SmartXManagedOverrideDiskState {
    case missing
    case currentOrCompatible(SmartXManagedOverride)
    case futureSchema(version: Int, rawData: Data)
    case unreadableOrIncompatible(String)
}

2. Implement a lightweight schemaVersion reader that does not require decoding the full SmartXManagedOverride model.

It should:
- Read raw Data from Paths.smartXManagedOverrideURL.
- Try to parse top-level JSON object.
- Extract schemaVersion if present.
- If schemaVersion > currentSchemaVersion, return futureSchema even if the full model cannot decode.
- If schemaVersion is absent or invalid but the file exists, treat as unreadableOrIncompatible, not missing.

3. Update bootstrapIfNeeded():

- If file is missing:
  - migrate legacy settings if they exist.
- If file is currentOrCompatible:
  - applyToSettings.
- If file is futureSchema:
  - log warning.
  - do not overwrite.
  - if compatible fields can be decoded safely, optionally apply known fields.
  - otherwise leave current UserDefaults/runtime settings unchanged.
- If file is unreadableOrIncompatible:
  - log warning.
  - do not overwrite.
  - do not migrate legacy settings over it.

4. Update unsafeFutureSchemaVersionOnDisk():

- It must detect future schema from raw JSON, not only after successful full decode.

5. Update persistCurrentSettings():

- If disk state is futureSchema, return .skippedFutureSchema(version:).
- If disk state is unreadableOrIncompatible, return a non-overwriting failure result.
  You may add:
  case skippedUnreadableExistingFile(String)
  or use .failed(String), but it must not overwrite the file.

6. Update SmartXManagedOverridePersistenceResult:

Add a user-visible warning for unreadable/incompatible existing override file:
- "Applied runtime settings, but did not overwrite the existing SmartX managed override file because it could not be decoded safely."

7. Update smartx_managed_override_smoke.swift:

Add tests for:

- A future-schema JSON file with extra unknown top-level fields but still decodable.
- A future-schema JSON file that is not decodable into SmartXManagedOverride but has schemaVersion > currentSchemaVersion.
- An unreadable/incompatible JSON file that exists and has no usable schemaVersion.
- bootstrapIfNeeded must not overwrite either future-schema or unreadable existing files.
- persistCurrentSettings must return a visible skipped/failed result and preserve file contents.

Acceptance criteria:

- Existing future-schema files are never overwritten during bootstrap.
- Existing incompatible override files are never overwritten during bootstrap.
- Future-schema detection does not depend on full Codable decode success.
- UI can surface non-persistence result through LightGBMSettingsViewModel.
- Smoke harness covers these cases.
